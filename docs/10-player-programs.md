# 10. Программы игроков

Игрок загружает одну программу под своей учётной записью. Идентификатор берётся из `sub` действующего JWT. Программа хранится в памяти сервера по идентификатору игрока, поэтому её можно загрузить до старта боя и использовать в разных партиях с подходящими JWT. Повторная загрузка заменяет программу. После перезапуска её загружают заново.

## Запуск

На сервере с Linux-контейнерами Docker заранее загрузите образы:

```powershell
docker pull python:3.12-alpine
docker pull node:22-alpine
```

Сервер поддерживает `python` и `javascript`. Список возвращает `GET /programs/languages`. Список секций языков задаёт `PlayerPrograms:Languages`. Каждая секция указывает имя языка, доверенный образ, исполняемый файл, аргументы и путь к служебному скрипту `Bootstrap` относительно каталога приложения. При сборке и публикации скрипты копируются из `PlayerPrograms/Bootstraps`.

Укажите в `$source` путь к файлу вашей программы, а в `$token` — JWT игрока для партии `match`.

```powershell
$headers = @{ Authorization = "Bearer $token" }
Invoke-RestMethod -Method Put -Uri 'http://localhost:5000/players/me/program/python' `
    -Headers $headers -ContentType 'text/plain; charset=utf-8' `
    -InFile $source
Invoke-RestMethod -Method Post -Uri 'http://localhost:5000/games/match/program/run' -Headers $headers
```

Для JavaScript используйте путь загрузки `/players/me/program/javascript`. Запрос запуска выполняет один ход в запущенной партии. Игроку требуется действующий корабль и право отправлять `FleetOrder`.

## Протокол хода

Программа читает один JSON-объект из stdin. В нём идентификаторы партии и игрока и текущий список его действующих кораблей:

```json
{"gameId":"match","playerId":"p1","ships":[{"id":"s1","kind":"Ship","position":[0,0],"direction":0,"fuel":20,"ammo":4}]}
```

Состав списка определяется разрешением `Fleet.ReadShipState`. При старте или восстановлении согласованной партии каждый участник получает это разрешение в области своей флотилии. Права на движение, поворот и другие приказы проверяются при обработке самого приказа.

`direction` — числитель игрового угла. Отсутствующие свойства корабля представлены как `null`. В stdout программа пишет `null`, чтобы пропустить ход, или один объект:

```json
{"id":"s1","action":"Rotation"}
```

Контекстный приказ может содержать `roles`, например `{"id":"t1","action":"Refuel","roles":{"Target":"s1"}}`. Сервер сам добавляет имя команды и идентификатор партии из JWT. Приказ идёт через обычный приёмник сообщений, настройки прав и дерево флотилий. HTTP 202 обозначает постановку в очередь, 204 — пропуск хода, 422 — ошибка программы или формата её ответа, 503 — недоступность Docker, образа или свободного места запуска.

## Изоляция и расширение

На каждый ход создаётся новый контейнер с отключённой сетью, файловой системой только для чтения и временной областью `/tmp`. Код запускается под непривилегированным пользователем. Контейнеру не передаются JWT, ключ подписи, каталоги хоста или Docker socket. Размер программы ограничен 64 КиБ, stdout — 16 КиБ, срок запуска — 10 секунд. Одновременно работают до двух запусков на HTTP-хост. После завершения или отмены сервер удаляет контейнер.

Если запрос отменён во время создания контейнера, сервер ждёт ответ Docker в пределах таймаута хода и переходит к очистке. Удаление по заранее заданному имени выполняется с отдельным таймаутом, в том числе когда Docker не подтвердил создание. Если такое удаление вернуло ошибку, сервер проверяет, остался ли контейнер с этим именем.

`IPlayerProgramStore` атомарно заменяет исходник одного игрока. `IPlayerProgramLanguage` принимает исходник, состояние хода и токен отмены, затем возвращает stdout. Реализация отвечает за изоляцию и ограничения запуска. Ошибка программы передаётся как `PlayerProgramException`, сбой среды или очистки — как `ProgramSandboxUnavailableException`. При успешной очистке отменённый запрос завершает `OperationCanceledException`. Docker-параметры принадлежат адаптеру `IPlayerProgramSandbox` в HTTP-проекте. Новый язык достаточно зарегистрировать по `IPlayerProgramLanguage`.

Общий валидатор применяет предел stdout и проверяет JSON для всех языков. `IPlayerProgramGame` получает типизированный `ProgramOrder`, в котором есть только `id`, `action` и `roles`. Личность игрока передаётся отдельно из JWT.

Секция `PlayerPrograms:Limits` задаёт пределы исходника, stdout и вложенности JSON. Секция `PlayerPrograms:Docker` задаёт имя клиента Docker, таймауты и лимиты контейнера. Контейнер ASP.NET внедряет настройки в HTTP-обработчик, проверку протокола и исполнителя. Пределы можно переопределить, например переменной `PlayerPrograms__Limits__OutputBytes`.
