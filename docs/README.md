# SpaceBattle — документация проекта

Состояние на **9 ноября 2026**. Репозиторий: https://github.com/stwz13/SpaceBattle. Язык документации — русский, идентификаторы — как в коде.

## Что это

Игровой сервер для «Космического боя». Умеет:

- выполнять игровые действия как **команды** (движение, поворот, топливо, дозаправка, стрельба, столкновения, урон);
- держать **много игр одновременно**: каждая игра — отдельная очередь команд со своим IoC-скоупом и своим хранилищем предметов;
- раскладывать игры по **серверным потокам** через кольцо консистентного хэширования (с необязательным ограничением нагрузки);
- принимать **JSON-сообщения** по HTTP, проверять JWT игрока, белый список команд и права игрока на предметы;
- **сохранять игры в JSON** и восстанавливать (по одной и всем сервером), **переносить игру** на другой сервер без потери сообщений;
- **добавлять и удалять потоки** на лету с перераспределением игр;
- реагировать на ошибки команд по настраиваемой политике (повтор, пропуск, остановка игры или потока).

## Сервер за две минуты

```
игрок ──HTTP POST /messages (Bearer JWT)──► ApiEndpoints
        │ проверка токена → PlayerIdentity{PlayerId, GameId, CanTransfer}
        ▼
AuthenticatedMessageReceiver:  разбор JSON → тот ли это игрок/игра → белый список команд
        ▼
GameHost.Send → PostToGameCommand → очередь серверного потока (приоритетная)
        ▼
поток: GameRunner → Game.Execute (квант времени, скоуп игры)
        ▼
InterpretMessageCommand → [проверка прав игрока] → [политика ошибок] → Messages.Command.<имя>
```

Игра хранит **предметы** (`IGameItem` — словарь свойств с обязательными `Id` и `Kind`) и очередь команд. Всё остальное сервер делает вокруг этого.

## Важное, что стоит знать сразу

- **Состав веток разный.** Серверный стек (потоки, HTTP, снимки, перенос, JWT) и игровые команды (движение, стрельба, тики и т. д.) лежат в разных ветках и пока не объединены в одну сборку. Подробности — [01-branches.md](01-branches.md).
- Сервер сам по себе регистрирует только одну игровую команду-сообщение — `CreateItem`. Остальные команды протокола приложение регистрирует под ключом `Messages.Command.<имя>` ([04-ioc-keys.md](04-ioc-keys.md) §F).
- Есть **две системы прав**, не связанные друг с другом: `Authentication/*` (JWT игрока, владение предметами, серверные ветки) и `Authorization/*` (дерево областей доступа и наследуемые разрешения, ветка `object-authorization`).
- В проекте **два `ICommand`**: `App.ICommand` (из `core.dll`, только для IoC) и `SpaceBattle.Lib.ICommand` (все игровые команды).
- Жёсткие правила кода проверяются тестом: **нет `for`/`while`** в `SpaceBattle.Lib`, **нет `Ioc`** в предметных папках ([05-conventions-and-ci.md](05-conventions-and-ci.md)).

## Словарь

| Термин | Значение |
|---|---|
| Предмет (`IGameItem`) | игровой объект: словарь свойств `GetProperty/SetProperty`; у созданного через `Items.Create` есть `Id` и `Kind` |
| Вид предмета (kind) | имя типа предмета (`Ship`) и список его свойств для снимка (схема `Serialization.Schema.<kind>`) |
| Адаптер | сгенерированный класс, который представляет `IGameItem` как узкий интерфейс (`IMoving`) |
| Действие (Action) | именованная макрокоманда, шаги которой перечислены в `Config/<Action>.config` |
| Контекстная команда | команда над несколькими предметами по ролям (`ICommandContext`: Target, Source) |
| Бой (`IBattleContext`) | идентификатор игры и хранилище её предметов |
| Квант (`IQuantum`) | отрезок времени, который игра имеет на выполнение команд за один заход на поток |
| Тик игры | запланированный шаг мира с фиксированным периодом; не то же самое, что квант |
| Управляемая игра (managed host) | игра вместе с её потоком, состоянием (`Running/Moving/Moved/Stopped`), паузой, переносом и снимком |
| Снимок | JSON игры: `gameId`, предметы, команды из очереди |
| Скоуп | область IoC; у каждой игры своя, у сервера — своя |

## Как поддерживать документацию

- Менять документ вместе с кодом, который он описывает; при расхождении правим документ.
- Цифры тестов и покрытия брать только из свежего прогона `dotnet test`. Если факт не проверен, писать «уточнить».
- Описания ключей IoC сверять с `Dependencies/*Dependencies.cs`.
