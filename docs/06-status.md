## 2. Тесты и покрытие

В этой документации **цифры не приводятся**: последний полный прогон выполнялся до перебазирования стека на новое состояние (`server-host`, PR #35 влит, #38 перенесён). Получайте свежие числа командой из [05-conventions-and-ci.md](05-conventions-and-ci.md) §4 и записывайте их здесь вместе с SHA ветки.

Для ориентира: по прежнему аудиту серверные ветки проходили все тесты (около 500 на верхушке стека), покрытие строк было около 99 %, ветвей около 94 %; результат не перепроверен.

Предупреждения сборки: `xUnit1031` возможны только там, где остались блокирующие ожидания в тестах.

## 3. Известные ограничения

1. **Снимок игры сохраняет из очереди только команды-сообщения**; любая другая команда → ошибка снимка.
2. `GameItemStorage.Add` не проверяет, что ключ равен свойству `Id` предмета.
3. Функция записи значения в кодеке снимка не получает доступа к самому кодеку, поэтому вложенные составные значения приходится записывать вручную.
4. `Game.Execute` исключения не перехватывает; политика ошибок (`#31`) действует только на команды-сообщения. Обработчика уровня игры для остальных команд нет.
5. Игровые команды (движение и др.) не зарегистрированы как `Messages.Command.<имя>` в серверном приложении, поэтому HTTP-сервер из коробки умеет только `CreateItem`.
6. Две системы прав (`Authentication/*` и `Authorization/*`) не связаны.
7. Единая сборка «сервер + игровые команды» не проверена: возможны конфликты в `ServerThread`, очередях, `IExceptionHandler`, `ServerThreadDependencies`.
8. Добавление `world-update`/`game-ticks` к серверному стеку по прежнему аудиту упирается в архитектурный тест по `Scheduling` (не перепроверено).
9. В `HostComposition` словарь получателей переноса пуст: перенос игры по HTTP отвечает `404`, пока приложение его не заполнит.
10. Архитектурный тест запрещает `for`/`while`, из-за чего циклы «по условию» приходится писать через LINQ — правило стоит пересмотреть отдельным решением.

## 4. Планы (из ROADMAP)

- Обход пар предметов мира для проверки столкновений (отдельная ветка). Открытый вопрос: достаточно ли пар «корабль — торпеда».
- Единые имена веток (`tanker-refuel` ↔ `refuel`, `game-ticker` ↔ `game-ticks`).
- Команды игры как сообщения через общий конвейер и сквозной тест, где они приходят сообщениями.
- Обработчик исключений уровня игры.
- Слияние стека PR в `main` по порядку ([01-branches.md](01-branches.md) §5).

## 5. Открытые вопросы (уточнить, не выдумывать)

1. Как именно собирать итоговое приложение: сервер и игровые команды в одной ветке или двумя модулями.
2. Где хранить JWT-секрет и как выдавать токены игрокам (в проекте нет сервиса выдачи токенов).
3. Нужен ли сетевой протокол между серверами для `IRemoteServer` (сейчас только интерфейс и HTTP-вход для переноса).
4. Нужно ли свести две системы прав в одну.
