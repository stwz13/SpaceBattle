## 2. Тесты и покрытие

Команды для повторного прогона приведены в [05-conventions-and-ci.md](05-conventions-and-ci.md) §4.

## 3. Известные ограничения

1. **Снимок игры сохраняет из очереди только команды-сообщения**; любая другая команда → ошибка снимка.
2. `GameItemStorage.Add` не проверяет, что ключ равен свойству `Id` предмета.
3. Функция записи значения в кодеке снимка не получает доступа к самому кодеку, поэтому вложенные составные значения приходится записывать вручную.
4. `Game.Execute` исключения не перехватывает; политика ошибок (`#31`) действует только на команды-сообщения. Обработчика уровня игры для остальных команд нет.
5. Для приёма движения, стрельбы и других игровых действий по HTTP нужно зарегистрировать команды сообщений, настроить белый список и права игрока.
6. `Authentication/*` проверяет права игрока в серверном конвейере, а `Authorization/*` реализует самостоятельную модель разрешений по областям.
7. В `HostComposition` словарь получателей переноса по умолчанию пуст. Запрос с неизвестным получателем возвращает `404`.

## 4. Планы (из ROADMAP)

- Определить, какие пары проверять помимо пары «корабль — торпеда», при подключении тиков в конкретной игре.
- Единые имена веток (`tanker-refuel` ↔ `refuel`, `game-ticker` ↔ `game-ticks`).
- Команды игры как сообщения через общий конвейер и сквозной тест, где они приходят сообщениями.
- Обработчик исключений уровня игры.

## 5. Открытые вопросы (уточнить, не выдумывать)

1. Где хранить JWT-секрет и как выдавать токены игрокам. В проекте есть проверка токенов, их выдачу обеспечивает приложение.
2. Нужен ли сетевой протокол между серверами для `IRemoteServer`. HTTP-вход инициирует перенос, а получатель предоставляется приложением.
3. Нужно ли свести две системы прав в одну.
