# 10. Транзакционные действия

Транзакция охватывает все шаги обычной макрокоманды, выполненной через `Commands.Action` или `Commands.ContextAction` (`CommandContextDependencies.Action`). Состав и порядок шагов по-прежнему задаются в `Config/<Action>.config` или в согласованном правиле.

## Подключение к HTTP-хосту

Разрешите транзакции в настройках сервера. Например, в PowerShell из корня репозитория:

```powershell
$env:Transactions__Enabled = 'true'
dotnet run --project SpaceBattle/SpaceBattle.Http
```

В предложении правил включите `Transactions.Enabled` один раз для всей игры. В `actions` перечислите обычные шаги:

```json
{
  "parameters": { "Transactions.Enabled": true },
  "actions": {
    "Movement": [
      "Commands.SpaceBattle_Lib_CheckFuelCommand",
      "Commands.SpaceBattle_Lib_MoveCommand",
      "Commands.SpaceBattle_Lib_BurnFuelCommand"
    ],
    "Shooting": ["Commands.SpaceBattle_Lib_ShootCommand"],
    "Refuel": ["Context.Refuel"]
  }
}
```

При отсутствующем параметре игры или значении `false` действия выполняются в обычном режиме. Сервер с выключенной функцией отклоняет значение `true`. Снимок игры сохраняет параметр вместе с обычным составом действий. Для восстановления или переноса такой игры разрешите транзакции на сервере назначения.

Для самостоятельной сборки приложения вызовите `RegisterIoCDependencyActionTransactions` в IoC-скоупе игры после настройки обычной композиции. Передайте коллекцию явно поддерживаемых побочных эффектов, например `[new ProjectileInsertionEffect()]` для штатного выстрела.

## Добавление команды

Подключите класс команды, адаптер и ключ обычным способом. Добавьте ключ в список шагов нужного действия. Сеттеры, сгенерированные для нового адаптера, подключаются к журналу автоматически. Для стандартной записи свойств дополнительных классов и регистраций отката нет.

Чтобы отменять особый побочный эффект, зарегистрируйте `ITransactionCommandEffect` с ключом соответствующей команды. Для HTTP-хоста его можно добавить в DI. Декоратор получает исходную команду и `ITransactionUndo`. Он должен учесть случай, когда операция успела изменить состояние и выбросила исключение. Для штатного выстрела хост подключает `ProjectileInsertionEffect`. Боезапас журналируется через сеттер, а вставленный снаряд удаляется с проверкой идентификатора и экземпляра.

## Границы отката

Включение параметра добавляет в область игры декораторы `Commands.Action` и `Commands.ContextAction`. Они вызывают исходные стратегии композиции в дочерней области с обёртками зарегистрированных сеттеров `Properties.<вид>.<интерфейс>.<свойство>.Set`. Транзакция сохраняет фактическое предыдущее значение перед каждой записью и восстанавливает его на том же экземпляре. Вложенные макрокоманды используют общий журнал с собственными точками отката.

Свойство должно существовать к моменту записи, поскольку `IGameItem` не умеет удалять свойство. Прямые записи в `IGameItem`, изменения вложенного объекта по ссылке и вызовы внешних ресурсов требуют явной компенсации.

Штатный сервер добавляет `Destroyed = false` для предметов вида `Ship` при создании и восстановлении, если значение отсутствует. Явно заданные значения `true` и `false` остаются в силе. При записи нового снимка сервер включает `Destroyed` в настроенную схему `Ship`.

Один шаг длительного движения и действие `Hit` получают собственную транзакцию при вызове штатной композиции. Весь тик мира и операции обработки попадания за пределами действия `Hit` выполняются за границей этой транзакции.

После успешного отката исходная ошибка передаётся обычному обработчику. Если операция отмены падает, журнал пытается выполнить остальные операции, транзакция останавливает затронутую игру и сообщает обе ошибки в `TransactionRollbackException`.
